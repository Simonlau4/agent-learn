# Neat

收尾只做一件事：把本轮任务中已接受、以后还用得上的结论、纠偏与根因做法，写到唯一正确的位置。用户直接点名要记某条经验或规则时，跳过翻找整场对话，直接把这一条写进对应位置。没有长期结果就直接结束，不写文件，回复里也不加收尾说明。

共享规则、长期事实与技能以工作区根配置、本地知识库或统一技能仓库为准；各 Agent 的原生记忆和单端目录（如 `~/.gemini/`、`~/.claude/`、`~/.codex/`、`.agents/`）只作定位线索，不单独存规则或技能副本。多 Agent 协作任务由主控在验收后统一写回，被委派方只在回报里列出待沉淀条目。

## 1. 纠正随时记下

用户纠正、否定或替换之前的结果、方向或做法时，在任务里用一句话记下最终生效要求并继续主任务；后一次纠正覆盖前一次。

收尾时逐条判断：以后还会用到才写回；一次性措辞调整、当前特例或情绪反馈不写。

## 2. 写什么

- 只写现在为真的正向事实、决策与现行规则；新结论修正或替代旧条目时，直接在原位置覆盖旧文并标绝对日期（`YYYY-MM-DD`），已有等价内容不再追加。
- 被否决的方案、报错流水账和验证过程不进当前状态文档。
- 排障试错多次才跑通时，对比失败尝试找出最后真正起作用的根因，把经验写成可以直接照做的做法：什么情况下、怎么做（精确命令、参数或判据）、看什么结果。
- 不写“X 不等于 Y”式的泛化告诫，不把一次性要求写成通用规则，不写事故经过或过错叙述。

## 3. 写到哪里

按当前工作区结构自动匹配落点，不擅自新建冗余目录：

| 场景或内容 | 唯一落点 |
| --- | --- |
| 已有分层知识库 / Vault（根 `AGENTS.md` 或 `CLAUDE.md` 含目录路由表） | 严格按既有路由落到最窄对应文档：项目事实进项目主页或现行页，个人偏好进偏好正本，跨周期判断进判断页，工具坑点进对应手册或能力地图 |
| 普通仓库：跨会话硬约束、协作与交付规矩 | 根 `AGENTS.md`（仅使用 `CLAUDE.md` 的项目写 `CLAUDE.md`） |
| 普通仓库：命令参数、排障坑点与模块说明 | 对应工具或模块的 `README.md`、`docs/` |
| 任务进度：未完结、下次要接着做的事项 | 项目当前状态入口或 `handoff.md`（写清进度、卡点和下一步） |
| 长期工作流与技能演化候选 | 仓库或知识库的共享工作流、候选目录 |
| 从零初始化（仅用户明确要求新建骨架时） | 按 [bootstrap-template.md](references/bootstrap-template.md) 建最小三分区：`AGENTS.md` + `Knowledge/` + `Memory/` + `Workbench/` |

同一事实只写一处，其他地方用链接指过去；优先更新已有条目，新增文件从根入口或索引页链入。运行日志、临时脚本、缓存与测试数据留在工作或临时目录，不升格为长期知识。

## 4. 写之前与写之后

- 写前读目标文件当前版本；顺带发现明显过时的文字或断链直接修正。
- 价格、参数、政策、权限、线上状态与 CLI 行为先回真实环境或源码核验；来源对不上时，把候选改动和依据告诉用户，这一条先不写，其余照常完成。
- 写后读回目标文件，确认下次新会话按检索顺序能从根入口、索引或能力地图找到它；深层文档缺入口时顺手补一行链接或检索关键词。

## 5. 附带检查与授权边界

- 只看过 `--help` 输出或权限清单、尚未真实跑通并核对结果的工具路径，不写入手册或能力地图。
- 找工具或文档入口走了弯路（原本有说明却盲猜或翻找多处才命中）：在根 `AGENTS.md` 或 `README.md` 索引处补上关键词或链接指针。
- 已接受的纠正暴露了某个在用 Skill 的指令缺口时，先写候选或展示具体 `diff`，经用户看过并批准后再改在用 `SKILL.md`。
- 跨周期核心业务判断发生强化、推翻或新增时，先在回复里用一句话提出改法，用户确认后再改正文。
- 密钥、token、cookie 与账号密码只留在本地私密配置，不写入知识库或共享规则。
- Git 提交与推送、删除或移动文件、对外发送与权限变更，各自需要用户当次明确同意；删除优先移入系统废纸篓或回收站。

## 6. 回复

- 有写回时，简列修改了哪些文件与一句话改动。
- 因缺来源或待确认而未写的，单独说一句。
- 没有写回时不提收尾。
